# Minimax H3 Prompt Director

## 三层架构【2026-11-24 三层架构改造】

本包规则分三层，各司其职：

1. **契约层**：本文件「不变量契约」是全包唯一硬规则源，违反任一条即废包重写。references/templates/checklists 中与不变量重复的规则一律以契约为准。
2. **校验层**：`自检_提示词包.py`（位于 Comfyui_WP_Node_Group 包根，与自检_H3段间衔接.py 同级）对分段包做确定性校验——存在 FAIL 即不得交付，必须回改提示词包后重跑直至全绿。
3. **台账层**：`lessons.md`（本包根）记录全部实测事故（日期/事故/根因/对应不变量/校验函数）。规则正文不再携带事故案情叙述，排查与补丁溯源一律查台账。

**新事故处置流程**：台账加一行 → 契约加/改一条 → 校验函数补一个。规则散文不再膨胀。

## 何时使用

当用户给出类似以下简短指令时使用：

- “帮我写一个角色放大招命中巨兽的 H3 视频提示词”
- “把这段短描述扩成参考生视频提示词，要有冲击帧和音效”
- “按案例格式优化成完整分镜提示词”
- “我有人物图、场景图、招式图，帮我生成 7 秒战斗提示词”
- “两个角色在客厅相遇，生活流，5 秒”
- “四组机甲依次坠地，每次坠地要有音效峰值”
- “龙族少女昏迷着从高空坠落，砸穿屋顶”
- “两个跪地的角色，背上各骑着一个角色，超现实暗黑奇幻”
- “赛博朋克雨夜追逐，不在任何预设里”

## 核心目标

把用户的简短指令优化为 **可直接粘贴给 Minimax H3 的完整提示词**，默认包含：

1. 整体基调
2. 参考图绑定
3. 叙事顺序
4. 分镜时间轴
5. 冲击帧规则（如有单次命中顶点）
6. 音效分层
7. 负面约束与质量校验

## 工作流

1. **抽取八要素**：主体、目标、场景、动作/招式、风格、时长、参考图、冲击帧需求。
   - **【2026-11-24 时长闸门前移修订（第5次场景槽位案连带）】抽取完立即判时长与分段意图：①用户指令含"分成N段/分N段发给我/分段/长视频/每段X秒/段间衔接/无限续接"等意图词 → 无条件走第 9 步分段包路径；②总时长 >15s → 默认分段；③总时长 ≤15s 且无分段意图 → 一律输出单份提示词，禁止擅自分段（2026-11-24 10s 误分段实测：用户只写"10S时长"被自动拆成 2 段，明说"没要求分段被分段"）。**
2. **缺省推断**：缺失信息不反复追问；优先用占位符或通用描述补齐。只有缺少主体/目标/场景导致无法成片时，最多追问 3 个关键问题。
3. **风格决策（四步，预设不是封闭清单）**：
   - **3.1 预设匹配**：先看用户需求能否命中 `references/style-presets.md` 中某个预设。命中则直接用预设，补差异维度。
   - **3.2 参数化组合**：若不完全命中，用参数化 7 维度（风格质感、渲染管线、天光氛围、色彩主调、节奏结构、镜头语言、音效基调）组合出风格骨架。
   - **3.3 最近邻派生**：若接近某个预设但不完全匹配，保留最近预设的渲染管线、节奏结构、镜头语言，只改风格质感、天光氛围、色彩主调、音效基调中差异的维度。
   - **3.4 用户自定义注入**：若完全不接近任何预设，或用户直接给出完整风格描述，不强行套预设；按参数化维度整理成连贯“整体基调”句式，并按风格质感就近推断镜头语言与音效基调。
   - 无论哪一步，最终都落到 7 维度参数化表，保证整体基调可读、连贯、不堆关键词。
4. **建立参考绑定**：分别绑定主体、招式/特效、目标、场景、冲击帧参考图。

### 4.1 编号规则【2026-11-24 标签化修订】

- 绑定行一律以 **@ImageN 标签**开头（如“@Image1（主体绑定）”“@Image3（场景环境绑定）”），N=参考图上传顺序，从 @Image1 开始连续编号，不跳号、不重复。
- **编号严格=用户上传顺序，禁止按叙事用途顺序重排**【2026-11-24 25s 测试包修订】：用户指令里的“图N”就是 @ImageN。排版习惯（主体→场景→目标）不得改变编号——用户传图1男子+图2怪兽时，怪兽绑定写 @Image2，没有场景图就不造场景绑定行。编号错位会让模型拿错参考图（怪兽图被当场景参考）。
- 不得沿用参考案例原始编号（如案例里是 @Image1、@Image2、@Image3、@Image5，新提示词也必须从 @Image1 连续排）。
- 场景环境绑定**必须带编号**，不能写“@ImageN（场景环境绑定）”不带具体编号。
- 单主体时：@Image1（主体）→ @Image2（招式/特效）→ @Image3（目标）→ @Image4（场景环境）→ @Image5（冲击帧）。
- 多主体时：@Image1（主体）、@Image2（主体）……依次顺延，后续绑定编号随之顺延。
- 多目标时：@ImageN（目标）、@ImageN+1（目标）……依次顺延。
- 无冲击帧时：不写冲击帧绑定，编号到场景环境图为止。
- **绑定区块末尾必须写“标签用途映射”行**：每个 @ImageN 一句话写清锁定对象与用途（如“@Image1 锁定图1男子的面部与服饰；@Image2 锁定图2女子的面部与服饰；@Image3 锁定古代长街场景”）。正文/镜头/配对中的“图N”称呼一律经此映射行与 @ImageN 衔接。

### 4.2 多主体规则

- 多主体时**分别绑定** @Image1（主体）、@Image2（主体）……，每个主体写清独立识别特征（发型、服装、配饰、比例）。
- 不得把多主体合并成一条绑定糊在一起写。
- 多主体同框时，必须写清前景/后景关系、谁先入画、谁抬头回应。
- 多主体存在配对关系（骑乘/承托/拉扯/并肩/对峙/拥抱/对视）时，必须在参考图绑定末尾补一条**配对关系**说明，不得只在镜头里补。
- 多主体复杂关系时，镜头按“全景确立关系 → 分主体近景 → 回到同框”分述。

### 4.3 多动作峰值规则

- 连续硬着陆、连续坠地、连续多次命中类动作，使用 **“硬切 + 动作峰值音效”**，**不插入静态冲击帧**。
- 冲击帧只用于**单次命中顶点**（单次招式命中、单次封印命中、单次碰撞顶点）。
- 多动作峰值时，每次动作单独标注一个峰值时间段，峰值之间用环境底噪、破空声过渡。
- 穿透式硬着陆（单主体砸穿一层再落到下一层）属于因果链连续动作，不插入冲击帧，每次硬着陆独立标注、独立峰值。

### 4.4 无冲击帧规则

- 环境叙事类、纯动作类、纯氛围类、情绪特写类、生活流、视线交汇类**不插入冲击帧**。
- 无冲击帧时，音效峰值改为：
  - 对准情绪顶点（如“峰值卡点对准 4.0–4.6s 双人视线交汇”）
  - 对准动作顶点（如“峰值卡点对准每次硬着陆瞬间”）
  - 对准喜剧张力顶点（如“峰值卡点对准 4.0–4.6s 三人拉扯顶点”）
  - 纯氛围类写“以层次递进为主，无单点峰值”

### 4.5 角色持续状态规则

- 主体处于昏迷、沉睡、被束缚、被定身、无意识、僵直、石化、被操控等持续状态时，必须在主体绑定中写明“全程保持XXX状态”+ 具体表现（眼睛、头部、四肢、表情）。
- 后续每个镜头的子时间段必须重复强化该状态。
- 负面约束必须写明“全程保持XXX状态，不{睁眼/做表情变化/挣扎/自主动作}”。

### 4.6 多主体互动音效归属规则

- 多主体互动音效必须写清声源归属：A 对 B 的动作音效 / 双方叠加音效 / 同步动作音效。
- 必须写清作用部位（肩部、左臂、右臂、龙角、背部）与动作性质（轻触、拉扯、承压、前压、开合）。

### 4.7 表演子层启用规则

- 情绪特写、生活流、视线交汇、多主体对峙/拉扯/互动、剧情向叙事类场景，按 `references/performance-layer.md` 启用表演子层：用六条表演轨道（眼神/面部/头肩/手部/身体/呼吸声音）把情绪写成可见的连续表演。
- 大招命中、连续硬着陆、纯能量突进、纯环境氛围类**不启用**表演子层；用户要求战斗中的表演时，只在蓄能近景、收尾互动等写实镜头局部加入，**不进冲击帧、不进音效峰值结构**。
- 表演子层不改变交付格式：表演细节只注入参考图绑定（表情气质边界）、镜头子时间段（可见动作）、音效设计（呼吸与情绪声音）、负面约束（表演类禁止项）四个位置。
- 启用时遵守：一段一个主动作、先视线后表情、段间留物理痕迹、状态变化有触发、情绪转换三阶段、四档强度同步影响幅度与呼吸。

### 4.8 硬切同步音效规则

- 每个硬切点（硬切转场、硬切进入、发动瞬间硬切）必须在音效设计中标注【切镜同步音效点】或写明切镜同步音效。
- 该规则不限于冲击帧场景；无冲击帧的生活流、情绪特写、多主体互动类同样适用。

### 4.9 台词规则

- 用户输入出现“说/喊/骂/吼/对话/交谈/争吵/低语”等台词意图词、但未给具体台词时，按 `references/performance-layer.md` 的“台词补全规则”自动补全具体台词（含引号、音量语速、音效说话声），不得降级为气音。
- 无台词场景，负面约束必须写“无台词，不生成清晰说话口型”；正文不得描写开口说话、说话口型、说完一句话。
- 有台词时，正文、音效、负面约束三处一致；负面约束不写“不生成清晰口型”，改为“台词与口型自然同步”。

### 4.10 运镜规则

- 镜头段的“镜头运动”按 `references/camera-motion-layer.md` 的运镜库选型，用标准句式（正向化写法，不用裸否定），复杂运镜（环绕/子弹时间/翻滚/螺旋）必须给圈数+时长。
- 运镜强度必须匹配场景：情绪特写、生活流、视线交汇类用**克制档**（禁用子弹时间/翻滚/螺旋/急推变焦/甩镜/整圈环绕/荷兰角）；动作、战斗、追逐类用**标准~剧烈档**。
- 复杂运镜只在用户点名或动作高潮用，不进情绪顶点、不进冲击帧结构。
- 本包为 prompt-only 不挂 LoRA；原运镜库标注“必须挂 LoRA”的运镜（整圈环绕、子弹时间、荷兰角）默认慎用。
- 遵守运镜核心纪律：不写该运镜以外的镜头变量（摇镜不写焦距、推拉必写焦距锁定、升降不写俯仰、横移不写“视线锁定主体”）；起手物写在最前面。

5. **排时间轴**：从 0.0s 开始，镜头段连续、无重叠，结束时间等于总时长。
6. **判断冲击帧**：若存在“单次命中顶点/碰撞顶点/封印命中/大招命中”，插入 0.15–0.2s 静态冲击帧；连续动作、环境叙事、情绪特写、生活流、氛围类不强行添加。
7. **写音效**：默认无 BGM，电影分层混音，峰值卡点对准冲击帧或主命中点；无冲击帧时按 4.4 规则处理。
8. **质量自检（两层）**【2026-11-24 三层架构改造；同日必过校验器修订】：①机器层——分段包交付前**必须实际运行** `自检_提示词包.py`（位于 Comfyui_WP_Node_Group 包根）校验 I1–I17 中可机器判定项，**任何 FAIL 都必须回改提示词包后重跑，直至 FAIL=0 才允许输出**——跑校验是硬命令、不是可选项，FAIL 回改是义务、不是"备注一句就绕过"（2026-11-24 重新生成包实测：生成侧明知 3+5+5+7=479帧=19.96s 残差 0.04s 是最优组合，却故意用 5+5+5+5=496帧=20.67s 残差 0.67s，还编"保持四段节奏一致"理由，在总控卡里自曝超限仍交付——这是"知道最优却故意不用+编伪解释"，比"不知道最优"更严重，禁止）；②人工层——I4 绑定零虚构、I8 空间调度由人工终审（参考 `checklists/quality-gate.md`，该清单已降级为参考性核对，硬规则以上方契约为准）。

## 关键原则

> 【2026-11-24 三层架构改造】可机器校验的硬规则已全部上收至「不变量契约」（帧数预算、时间覆盖、绑定标签、绑定零虚构、基调逐字、承接保持、事件唯一性、空间连续、台词一致、接缝音频），本节只保留不可机器校验的风格与结构原则。事故案情一律查 `lessons.md`。

- **结构复用，内容不污染**：不得大段拼接案例原文；不得复用案例专有名词、台词、牌匾文字、特定符号、角色设定。
- **预设不是封闭清单**：`style-presets.md` 是高频快捷方式，不是必选项清单；预设外风格用参数化维度组合、最近邻派生或用户自定义注入兜底，不得强行套错预设。
- **参考图优先**：角色外观、服装结构、目标体型、场景构件必须锁定参考图，不得漂移。
- **多主体分绑**：多主体分别绑定、分别编号、分别写识别特征；有配对关系时在参考图绑定末尾补配对关系说明。
- **持续状态三重强化**：昏迷/束缚/定身等持续状态必须在主体绑定、镜头子时间段、负面约束三处强化。
- **冲击帧是静态卡点**：不是爆炸过程、不是撕裂过程、不是慢动作，只表现单次命中顶点定格。
- **连续动作不做冲击帧**：连续硬着陆、连续命中、穿透式双硬着陆用硬切 + 动作峰值音效。
- **剪影优先**：冲击帧中主体与目标必须形成清晰粗黑轮廓剪影，特效不得遮挡剪影。
- **表演子层按场景启用**：情绪特写、生活流、多主体互动类启用表演子层；战斗结构（冲击帧、硬着陆、音效峰值）不插表演内容；表演细节只注入现有格式的四个位置，不新增交付段落。
- **整体基调要连贯**：无论预设内还是预设外，整体基调必须读起来是一段连贯描述，不是关键词堆砌。
- **硬切必配同步音效**：每个硬切点都必须在音效设计中标注【切镜同步音效点】或写明切镜同步音效。
- **运镜按强度匹配场景**：运镜从运镜库选型、用正向化标准句式；情绪特写/生活流用克制档，动作/战斗用标准~剧烈档；复杂运镜（环绕/子弹时间/翻滚/螺旋/急推变焦/甩镜/荷兰角）只在用户点名或动作高潮用，不进情绪顶点、不进冲击帧结构，且必须给圈数+时长。
